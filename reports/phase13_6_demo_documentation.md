# Offline Skin Lesion Analyzer — Demo Walkthrough

## 1. Launching the Application

The application is engineered for isolated, localized execution. Launch the Streamlit environment from your activated virtual environment utilizing the following command:

```bash
python -m streamlit run app/app.py
```
*(On Windows systems, if pathing issues occur, the direct executable can be used: `./.venv/Scripts/python.exe -m streamlit run app/app.py`)*

Upon successful execution, the application will initialize a local web server available in your browser at:
`http://localhost:8501`

**Note:** This application runs entirely offline.

## 2. Authentication

The Offline Skin Lesion Analyzer is protected by a localized security gateway.
- **First-User Setup:** On the very first launch, the system automatically detects an empty configuration and routes the user to an administrative setup screen. This generates the initial secure profile.
- **Login:** Users authenticate using a local username and password. 
- **Logout:** A logout button in the sidebar safely terminates the active local session.
- **Security:** Credentials are cryptographically hashed using PBKDF2-HMAC-SHA256. Plaintext credentials are never saved, and no cloud-based authentication (like OAuth) is utilized.

## 3. Image Analysis Workflow

Once authenticated, the UI strictly follows a linear, intuitive processing sequence:
1. **Upload image:** The user drops a JPG/PNG file into the main container.
2. **Analyze:** The system begins local preprocessing and image evaluation.
3. **Model output:** Inference completes and predictions display.
4. **Image quality:** Heuristic characteristics of the image are calculated.
5. **Grad-CAM:** The explainability visualization is rendered.
6. **History:** The session history table automatically reflects the new entry.

## 4. Model Output

Following inference, the user is presented with the statistical outputs generated by the fine-tuned EfficientNet-B0 model:
- **Model prediction:** The final classification string (e.g., "Non-malignant" or "Malignant-Suspicious").
- **Estimated model probability:** The continuous scalar derived from the Sigmoid activation function.
- **Probability distribution:** A continuous visualization bar indicating the balance between classes.
- **50% decision threshold:** The static boundary separating the binary prediction outcomes.
- **Threshold distance:** An absolute mathematical calculation representing the output's proximity to the 0.50 cutoff.
- **Model output strength:** A textual descriptor translating the threshold distance (e.g., "Near-threshold" or "Farther from decision threshold").

*Terminology Note:* These are statistical model outputs, not metrics of clinical confidence.

## 5. Image Quality

The application calculates programmatic image heuristics independently of the machine learning model:
- **Resolution:** Checks pixel dimensions.
- **Brightness:** Analyzes average luminosity to flag extreme darkness or overexposure.
- **Sharpness:** Analyzes variance of the Laplacian to identify severe blurring.

These basic image characteristics help explain failure conditions caused by poor photographic input, but they do not confirm medical image validity.

## 6. Grad-CAM

To interpret the model's behavior, the application generates a Gradient-weighted Class Activation Mapping (Grad-CAM) visualization. The user views:
- The **original image** side-by-side with the **Grad-CAM overlay**.
- The heatmap identifies the specific pixel regions contributing more strongly to the model's final mathematical output.

Grad-CAM is an explainability visualization designed to audit computer vision behavior; it is not a medical diagnostic map.

## 7. Prediction History

The application maintains a local logging system. The user can expand the Prediction History section to view:
- **Locally recorded outputs**: A tabular record of the current session's activity.
- **Data columns**: Timestamp, Image Name, prediction, probabilities, model output strength, and image quality metrics.
- This history is appended directly to a local CSV file (`history/prediction_history.csv`) and is never transmitted externally.

## 8. Theme Support

The application's UI, built on Streamlit, natively respects the host operating system's theme configurations. It fully supports:
- Light theme
- Dark theme
- System theme integration

## 9. Offline Operation

The application workflow operates with zero network dependencies. Image inference relies strictly on the local `best_finetuned_model.pth` checkpoint, and application processing, session management, and authentication occur exclusively on the local machine's processor. *(Note: The initial setup, such as cloning the repository or downloading the dataset/packages, requires network access, but the active runtime does not).*

## 10. Portfolio Demo Flow

For technical demonstrations or interviews, the following sequence effectively communicates the engineering architecture:
1. **Start the application** via the terminal command, proving localized execution.
2. **Show local authentication**, emphasizing the secure PBKDF2 hashing mechanics.
3. **Upload a representative skin-lesion image** from a local directory.
4. **Show Model Output**, emphasizing the statistical vocabulary and threshold boundary.
5. **Show Image Quality** and explain how heuristics catch extreme input variance.
6. **Show Grad-CAM**, explaining how it targets the final convolutional layer for visual explainability.

8. **Explain that processing occurs locally** without cloud endpoints.
9. **Briefly show evaluation results** (the ROC-AUC curve or confusion matrix) from the repository's `reports/` folder to anchor the application's statistical validity.
